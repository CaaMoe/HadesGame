# HadesGame（阴间游戏）

一个基于 Fabric 的 Minecraft 服务端大逃杀模组。玩家会被投放到随机地图中，在不断收缩的边界与持续刷新的随机事件里互相厮杀，最后只留下 1 名幸存者。

## 项目简介

HadesGame 是一个 **Server Only** 的 Fabric 模组，核心玩法是：

- 开局随机地图与大厅位置
- 玩家在等待阶段通过双击潜行切换准备状态
- 游戏开始后进入生存模式并获得短暂无敌时间
- 之后周期性触发各种“阴间事件”来扰乱战局
- 直到场上只剩最后一名非旁观者玩家

当前模组信息：

- 模组 ID：`hadesgame`
- 模组版本：`3.0-SNAPSHOT`
- 运行环境：`server`
- Minecraft 版本：`26.1`

## 主要特性

- 随机大厅与随机对局地图
- 多阶段游戏流程控制
- 自动记分板展示当前状态
- 双击潜行准备机制
- 大量即时/持续型随机事件
- 世界边界动态收缩
- 自动宣布胜者并重开下一局

### 同步与构建说明

项目已经补全 Gradle Wrapper，推荐统一使用：

```bash
./gradlew build
```

Windows 下可使用：

```bash
gradlew.bat build
```

如果你的本机 **JDK 25** 不在当前配置路径，需要修改 `gradle.properties` 里的这项：

```properties
org.gradle.java.installations.paths=D:/Java/openjdk-25
```

将其改成你自己的 JDK 25 路径即可，否则 IDEA/Gradle 在同步 `source sets` 时可能因为找不到 Java 25 toolchain 而失败。

构建产物默认位于：

```text
build/libs/
```

## 游戏流程

### 1. 地图初始化阶段

- 服务端启动后随机选择大厅/对局区域
- 在地图准备完成前，新玩家会被拒绝进入
- 初始化完成后生成大厅边界与落脚区域

### 2. 等待开始阶段

- 至少需要 **2 名玩家** 才能开局
- 玩家通过 **双击潜行键（Shift）** 切换准备/未准备状态
- 全员准备后开始倒计时并进入下一阶段

### 3. 游戏中阶段

- 所有玩家被重置状态并切换为生存模式
- 开局有 **20 秒无敌时间**
- 世界边界会从 `1000` 持续收缩到 `3`
- 随机会在一定间隔内触发事件
- 有一定概率出现 **FAKE EVENT**，只提示不生效

### 4. 结束阶段

- 当场上仅剩 1 名非旁观者玩家时结束
- 广播胜者并展示记分板
- 倒计时结束后自动开始下一局

## 随机事件一览

下面是当前项目中已经启用的事件及其作用：

| 事件名 | 类型 | 介绍 |
| --- | --- | --- |
| 黑暗降临 | 持续 30 秒 | 所有存活玩家获得失明与黑暗效果，视野被大幅限制。 |
| 连坐 | 持续 30 秒 | 随机为玩家两两配对，一人受伤时会把伤害同步给搭档；奇数人数时会有人轮空。 |
| 发光猎场 | 持续 30 秒 | 所有存活玩家进入发光状态，更容易被其他玩家追踪。 |
| 随机掉落 | 持续 30 秒 | 期间生成的掉落物会被替换为随机物品，战利品完全不可预测。 |
| 反向伤害 | 持续 30 秒 | 攻击别人时，伤害会反弹到攻击者自己身上。 |
| 禁疗时刻 | 持续 30 秒 | 期间对局内玩家触发的常规治疗会被直接拦截，回血手段整体失效。 |
| 狭路相逢 | 持续 30 秒 | 临时加速所有世界边界的收缩速度，30 秒后再恢复原本的边界计划。 |
| 均贫卡 | 即时事件 | 计算所有存活玩家的平均生命值与饱食度，并强制拉平。 |
| 热栏洗牌 | 即时事件 | 打乱所有存活玩家的快捷栏顺序。 |
| 装备轮换 | 即时事件 | 玩家之间轮换身上的护甲装备。 |
| 缴械风暴 | 即时事件 | 清空所有存活玩家的主手物品，并将物品直接丢到地上。 |
| 超级矿工 | 持续 30 秒 | 挖掉一个方块时，会顺带破坏周围一个 5×5×5 区域内的方块。 |
| 交换位置 | 即时事件 | 玩家之间互换当前位置。 |
| 饥荒模式 | 持续 30 秒 | 所有存活玩家的饱和度和饱食度会持续快速下降。 |
| 交换背包 | 即时事件 | 玩家之间交换当前背包内容。 |
| 超级减速 | 持续 30 秒 | 将服务器 Tick Rate 降到 10，整体游戏节奏变慢。 |
| 交换状态 | 即时事件 | 玩家之间交换生命值与饱食度。 |
| 雷暴点名 | 持续事件 | 每隔 4 秒随机点名一名玩家，在其附近生成装饰性闪电并全服提示。 |

## 特殊机制说明

除了上面的正式事件，当前对局里还有一些不以 `AbstractGameEvent` 形式存在、但会显著影响游戏体验的特殊机制：

### 1. FAKE EVENT（伪事件）

- 在游戏阶段，事件倒计时归零后不一定总会触发真实事件
- 当前逻辑下，大约有一部分概率只会广播 `FAKE EVENT`
- 伪事件只负责制造心理压力与误导，不会真正施加任何事件效果

### 2. 开局无敌时间

- 游戏开始后，所有玩家会进入生存模式
- 前 **20 秒** 为无敌期，期间不会受到正常对局伤害
- 无敌倒计时结束后，系统会全服提示并正式开战

### 3. 世界边界收缩

- 游戏开始时所有世界边界会被重置为 `1000`
- 之后边界会持续向更小范围收缩，最终逼迫玩家交战
- 记分板会实时展示当前边界大小

### 4. 双击潜行准备机制

- 在等待阶段，玩家不是单击，而是通过 **双击潜行键** 切换准备状态
- 任意玩家取消准备时，已经开始的开局倒计时也会被终止
- 只有当人数满足且所有玩家都准备完成时，游戏才会真正开始

### 5. 即时重生与旁观切换

- 模组会根据当前阶段接管玩家死亡后的处理方式
- 在等待/初始化阶段，玩家会被恢复状态并传回大厅
- 在正式对局阶段，玩家死亡后会切换为旁观者，直到本局结束

## 项目结构

```text
src/main/
├── kotlin/moe/caa/fabric/hadesgame/
│   ├── gameevent/   # 所有随机事件
│   ├── stage/       # 游戏阶段（初始化、等待、进行中、结束）
│   ├── handler/     # 玩家、死亡、伤害、记分板等处理逻辑
│   ├── event/       # 自定义事件桥接（死亡、实体 flag、治疗拦截等）

│   └── GameCore.kt  # 游戏核心循环
└── java/moe/caa/fabric/hadesgame/mixin/
    └── mixin/       # Mixin 注入与访问器
```

## 开发：注册一个新游戏事件

要注册一个新事件，只需要在 `moe.caa.fabric.hadesgame.gameevent` 包下新增一个 `AbstractGameEvent` 的 `data object` 子类，并实现对应逻辑。

```kotlin
data object ExampleEvent : AbstractGameEvent() {
    override val eventName = "你的事件名称"

    override fun initEvent() {
        /** 事件初始化逻辑 */
    }

    override suspend fun callEvent() {
        /** 触发事件时执行 */
    }

    override suspend fun endEvent() {
        /** 事件结束时清理 */
    }
}
```

### 事件编写建议

- 即时事件尽量只做一次性状态修改
- 持续事件记得在 `endEvent()` 中回收状态
- 涉及玩家状态同步时优先复用 `util/` 中的工具函数
- 如果事件需要拦截原版行为（如死亡、实体 flag、治疗），优先在 `event/` + `mixin/` 中补一层桥接，再由事件自己决定是否生效
- 涉及服务器底层行为时优先查看 `mixin/` 与 `handler/` 的既有实现
